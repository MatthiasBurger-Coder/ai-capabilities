# Lifecycle Work Record

Use with the [lifecycle workflow](../WORKFLOW.md). Keep relevant fields only;
record in chat or a requested artifact. Do not turn blank fields into invented
facts, execution evidence or approval.

## Task and starting state

- Request/event identity and actual source:
- Original request, goal, users, scope and non-goals:
- Acceptance criteria / requirement IDs:
- Existing candidate, source revision and local changes, if applicable:
- Referenced project policy/governance:
- Existing authorization, limits and reserved decisions:
- Known facts, assumptions and material open questions:
- Sourced vision and actual project profile used to select questions/process depth:

## Assessment and selected path

- Impact, uncertainty and reversibility with reasons:
- Affected data, interfaces, trust boundaries and external systems:
- Selected path and applicable phases:
- Phases not applicable and reasons:
- Selected perspectives, actual contributors and delegated scope:
- Actual key-user input versus unvalidated agent hypotheses:
- Specialist/operational decision owners when needed:

## Events and phase progress

Use the [transition template](transition-template.md) when a transition needs
detail. Record actual state and evidence per affected scope/discipline.

| --- | --- | --- | --- | --- |

| Phase | Inputs / candidate | Work performed | Artifact or observation | Exit met / blocked / not applicable and reason |
| --- | --- | --- | --- | --- |

## Decisions and authority

| Decision ID | Choice / alternatives / rationale | Scope and candidate | Authority mode / actual source or owner | Effects / recovery option | Outstanding decision / recheck |
| --- | --- | --- | --- | --- | --- |

For a required human decision, include the concrete proposal, prepared artifacts,
verified results, limitations, consequences and recovery option. Record the
actual response; absence of a response is not approval.

## Implementation and verification

- Candidate identity and changed artifacts:
- Relevant plan, prerequisites and deviations:

| Criterion / risk ID | Applicable check / command / procedure | Candidate / environment / substitutions | Actual result: PASS / FAIL / NOT_RUN / BLOCKED / NOT_APPLICABLE | Evidence / limitations / reason |
| --- | --- | --- | --- | --- |

- Applicable AI-product checks and rationale, if any:
- Old evidence reused and why it still applies:
- Open findings, affected scope, owners and resolution steps:

## Handoff and observed outcome

- Result and practical benefit:
- Acceptance criteria met and remaining limitations:
- Code/configuration/documentation or other requested delivery artifacts:
- Key assumptions, decisions and unresolved risks:
- Installation, deployment, rollback and support information where applicable:
- Task completion: COMPLETE / PARTIAL / BLOCKED with the exact boundary:
- Release readiness: READY / CONDITIONAL / NOT_READY / NOT_ASSESSED with evidence:
- Release authorization: actual source and scope / absent / not applicable:
- Deployment: actual observed candidate/environment/result / not performed:
- Operations: assigned owner/signals/observation window / outside task scope:
- Follow-up event, next action and responsible owner:

Keep round-table consensus, actual stakeholder confirmation and phase exit assessments
separate when attaching a Five Amigos report. A completed review is not a
completed implementation, and a verified candidate is not an observed rollout.
